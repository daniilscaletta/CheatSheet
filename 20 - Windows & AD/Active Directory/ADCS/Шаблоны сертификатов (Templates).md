#AD #ADCS #windows #templates

> **Templates** - самая интересная часть для атакующего

Шаблоны определяют **всё**: 
- кто может получить сертификат, 
- что в нем будет написано 
- для чего его можно будет использовать. 

<span style="background:#ff4d4f"> Именно здесь Blue Team чаще всего допускает ошибки, которые превращаются в ESC-уязвимости.</span>
### Ключевые атрибуты сертификата

1. **Permissions (Права доступа):** 
	- `Read`    - Кто может видеть шаблон  
	- `Enroll`- Кто может запрашивать сертификат 
	- `Autoenroll` - Позволяет системе запрашивать сертификат автоматически в фоне.

2. **EKU (Extended Key Usage):** Для чего предназначен сертификат 
	- вход в систему 
	- подпись кода
	- шифрование почты

4. **Subject Name:** Кто определяет имя в сертификате — сама система (на основе данных из AD) или пользователь при запросе (самый опасный момент!).

## **EKU (Extended Key Usage)**
**EKU - Это список OID (объектных идентификаторов), которые определяют назначение сертификата.

| **Название EKU**          | **Для чего нужен**                                     |
| ------------------------- | ------------------------------------------------------ |
| **Client Authentication** | Вход в систему, TLS-клиент, аутентификация в сервисах. |
| **Smartcard Logon**       | Специфичный вид входа именно через смарт-карту.        |
| **Server Authentication** | Идентификация сервера (например, для HTTPS).           |
| **Code Signing**          | Подпись исполняемых файлов.                            |

## **Subject Name**
Самое интересное для атакующего в случае *Supply in the request*

Режимы:
1. **Build from this Active Directory information:** Сервер сам берет твое имя                            (`sAMAccountName`) из базы и вписывает в сертификат. Ты не можешь прикинуться другим.

2. **<span style="background:#ff4d4f">Supply in the request:</span>** Ты сам отправляешь серверу строку: «Я — Администратор», и сервер вписывает её в сертификат.
