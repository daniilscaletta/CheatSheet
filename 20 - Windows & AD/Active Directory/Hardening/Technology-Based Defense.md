#hardening #windows #AD 

- Периодически запускайте такие инструменты, как <font color="#00b050">[[BloodHound]], PingCastle и Grouper, </font>для выявления ошибок в конфигурации Active Directory.

- Убедитесь, что администраторы не сохраняют пароли в поле описания учетной записи Active Directory.

- Проверьте раздел SYSVOL на наличие скриптов, содержащих пароли и другие конфиденциальные данные.

- Избегайте использования «обычных» учетных записей служб, по возможности применяйте групповые управляемые учетные записи (gMSA) и управляемые учетные записи служб (MSA), чтобы снизить риск [[Kerberoasting]].

- По возможности отключайте <font color="#00b050">неограниченное делегирование</font>.

- Предотвратите прямой доступ к контроллерам домена, используя защищенные промежуточные хосты.

- Рассмотрите возможность установки <font color="#00b050">`ms-DS-MachineAccountQuota`приписывать `0`</font>, что запрещает пользователям добавлять учетные записи машин и может предотвратить ряд атак, таких как атака noPac и делегирование с ограничением на основе ресурсов (RBCD).

- По возможности отключите службу диспетчера печати, чтобы предотвратить различные атаки.

- По возможности <font color="#00b050">отключите аутентификацию NTLM</font> для контроллеров домена.

- Используйте расширенную защиту для аутентификации, а также включите параметр «Требовать только SSL», чтобы разрешить HTTPS-соединения для служб веб-регистрации центра сертификации и веб-службы регистрации сертификатов.

- Включите  <font color="#00b050">SMB и LDAP - signing и channel binding</font>.

- Примите меры, чтобы предотвратить перепись с помощью таких инструментов, как BloodHound.

- В идеале, тестирование на проникновение/оценку безопасности Active Directory следует проводить ежеквартально, но при наличии бюджетных ограничений — как минимум ежегодно.

- Проверяйте резервные копии на достоверность и пересматривайте/отрабатывайте планы аварийного восстановления.

- Включите ограничение анонимного доступа и предотвратите перечисление нулевых сессий, установив соответствующий параметр. `RestrictNullSessAccess`ключ реестра для `1`ограничить доступ к нулевой сессии для неаутентифицированных пользователей.
