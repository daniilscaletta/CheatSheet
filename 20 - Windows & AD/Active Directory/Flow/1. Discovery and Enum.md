# Анализ протокола LDAP

LDAP - хранилище AD. Протокол для чтения и поиска данных в древовидном каталоге AD. 
В нем хранится:
- база данных пользователей
- справочник групп
- источник всей ифнормации

## Структура LDAP:

```
DC=edu,DC=stf
 ├── OU=Departments
 │    ├── OU=Operators department
 │    │     └── CN=g_rodriquez
 │    └── OU=Finance
 │          └── CN=j_smith
 └── OU=Computers
       └── CN=WIN-DC01
```

• **DC** — доменные компоненты (edu.stf)  
• **OU** — организационные единицы (отделы)  
• **CN** — конкретные объекты (юзеры, компьютеры)

## Тестирование

Узнаем DC
```shell
ldapsearch -x -H ldap://10.154.16.134 -s base namingcontexts
```

Логинимся под пользователем:
```shell
ldapwhoami -H ldap://10.154.16.134 -D 'r_andrews@edu.stf' -w 'dancer'
```

Ищем конкретную информацию
```shell
ldapsearch -x -H ldap://10.154.16.134 \ 
-D 'r_andrews@edu.stf' -w 'dancer' \
-b 'DC=edu,DC=stf' \

-s sub '(objectClass=*)' cn 
'(sn=Rodriquez)'
```

# Ручное тестирование
Мы можем использовать стандартные срадства, такие как PowerShell, чтобы изучить AD


### Get-ADUser
Получить инфу обо всех юзерах домена:
```powershell
Get-ADUser -Filter * -properties *
```

Получить инфу о потенциальных привилегированных записях
```powershell
Get-ADUser -filter {AdminCount -eq 1} -Prop AdminCount |` Select NAME, Enable, Objectclass, AdminCount |` Format-Table
```

Выявление привилегированных учетных записей со старыми паролями
```powershell
Get-ADUser -filter {AdminCount -eq 1} -Prop AdminCount |` Select NAME, DistinguishedName, PasswordLAstSet, AdminCount |` Format-Table
```

Идентификация привилегированных учетных записей с установленным SPN
```powershell
Gte-ADUser -Filter 'ServicePrincipalName -like "*" -and AdminCount -eq 1' -Properties ServicePrincipalName, AdminCount | ` Select-Object Name, ServicePrincipalName, AdminCount | ` Format-Table
```

Поиск всех установленных SPN
```powershell
Get-ADUser -Filter 'ServicePrincipalName -like "*"' -Properties ServicePrincipalName | ` Select-Object Name, ServicePrincipalName | ` Format-Table
```

Использование свойства `msDS-SupportedEncryptionTypes` для выявления билетов с обязательным шифрованием (Использовать до запроса билетов)
```powershell
Get-ADUser -Filter "ServicePrincipalName -like '*'" -Properties ServicePrincipalName, msDS-SupportedEncryptionTypes | ` Select-Object Name, msDS-SupportedEncryptionTypes, ServicePrincipalName | ` Format-Table -AutoSize
```

## SPN Scan
Service Principal Names сканирование используется для определения всех работающих сервисов, а также порты на которых они работают в домене через AD. Можно использовать и [[NMAP]], но SPN менее инвазивный, так как использует встроенные механизмы, предусмотренные AD

```powershell
ADForestInfoRootDomain = ([System.DirectoryServices.ActiveDirectory.Forest]::GetCurrentForest()).RootDomain

$ADForestInfoRootDomainDN = “DC=” + $ADForestInfoRootDomain -Replace(“\.”,’,DC=’)

$ADDomainInfoLGCDN = ‘GC://’ + $ADForestInfoRootDomainDN

$root = [ADSI]$ADDomainInfoLGCDN

$ADSPNSearcher = new-Object System.DirectoryServices.DirectorySearcher($root,”(serviceprincipalname=***sql***)”)

$ADSPNSearcher.PageSize = 500

$AllADSQLServerSPNs = $ADSPNSearcher.FindAll()

$AllADSQLServerSPNs
```

## Remote Sessions Enumeration
Это удаленный сбор инфы о текущих пользовательских сессиях на Windows-узле:
- кто залогинен локально (interactive);
- кто залогинен через RDP;
- кто держит SMB-сессию;
- кто подключён через WinRM/PowerShell Remoting;
- какие процессы от чьего имени работают;
- активность сеансов и их тип.
Это позволяет атакующему (или администратору) понять:
- кто сейчас на машине,
- с какими привилегиями,
- откуда они пришли,
- какие токены могут быть доступны

Получение инфы по AD

SharpHound - коллектрор (exe/ps скрипт)

```powershell
# Пример запуска SharpHound для сбора всех ключевых данных
```

BloodHound дает следующие возможности:
- найти аккаунты всех доменных администраторов;
- найти хосты, на которых залогинены доменные администраторы;
- построить кратчайший путь от хоста атакующего до хоста с сессией доменного админа

#### Использование
1) Скачиваем и запускаем Neo4j
2) Создаем пустую БД, запоминаем пароль
3) Включаем коллектор SharpHound, получаем архив с данными об AD
4) Аплоадим архив в BloodHound и смотри структуру

## 6) Анализ Sysvol

Путь до _sysvol_: \\\contoso.local\SYSVOL\contoso.local\Policies\id_GPO
В папке групповых политик нас интересуют файлы _XML_, которые могут содержать в себе «зашифрованный» пароль:

- _Groups.xml_.
- _Services.xml_.
- _Scheduledtasks.xml_.
- _DataSources.xml_.
- _Printers.xml_.
- _Drives.xml_.

Искать пароли и взламывать хэши можно при помощи [PowerSploit](https://github.com/SkillfactoryCoding/HACKER-OS-PowerSploit) либо прям PowerShell:

```powershell
findstr /S /I cpassword \\<FQDN>\sysvol\<FQDN>\policies\*.xml
```
