> _Link-Local Multicast Name Resolution_ (_LLMNR_) и _Netbios Name Service_ (_NBT-NS_) — компоненты _Windows_, позволяющие машинам, находящимся в одной подсети идентифицировать друг друга в случае недоступности _DNS_ либо как дополнительный источник информации.

### Приоритет разрешения доменных имен в Windows

1) Local name
2) DNS Cache `ipconfig /displaydns`
3) file `/etc/hosts` / `C:\Windows\System32\drivers\etc\hosts`
4) DNS сервер
	DNS Запрос СОСЕДЯМ
	4) LLMNR         ->   Компьютер рассылает запрос всем соседям по сети.
	5) NBT-NS       ->    Используются только с однокомпонентными  именами
	6) mDNS          ->    Используется для разрешения имен типа `hostname.local`

### Условия, необходимые для проведения атаки **LLMNR/NBT-NS poisoning**:

1) находится в одном широковещательном домене с целевым хостом,
2) наличие сетевой связанности по _udp_ портам 5355, 5353 и 137 между вами и целевым хостом,
3) _(опционально)_ любым способом сделать недоступной сетевую связь между _DNS_ сервером и целевым узлом.

##  Последовательность атаки:

1. При подключении на файловую шару _\\\pintserver_ (вполне очевидно, что изначально планировалось подключение на _\\\printserver_) происходит разрешение имени (разумеется, в кеше и в файлике _hosts_ такой записи нет) на _DNS_ сервере.
2. _DNS_ сервер возвращает ответ, что никогда о таком хосте не слышал (потому что слышал о _pRintserver_).
3. Перед тем как выдать пользователю ошибку о том, что такой хост не найден, будет сделан широковещательный запрос с целью найти у кого-то из соседей с помощью _LLMNR_ или _NBT-NS_ протокола.
4. Ну и конечно же, атакующий расскажет жертве, что знает такой хост (мне кажется, что атакующий всегда знает).
5. Целевой хост отправляет свои учётные данные с целью аутентификации и получения доступа к сервису.
6. Далее если хэши легкие, то можно использовать John The Ripper для вздлома
7. Иначе использовать атаку MultiRelay и аутенифицировать по хэшу

### Инструменты:

1) Responder
2) NTLMRelayx

## Responder

Основной Инструмент для этой атаки. Поднимает свой сервер и ловит broadcast запросы LLMNR/NBT-NS/mDNS и инициирует NTLM аутентификацию

Запуск Responder для прослушивания и отравления запросов
```bash
python3 Responder.py -I eth0 -wrf
```

## Митигации

- **Отключение LLMNR** – LLMNR можно отключить в редакторе групповой политики в меню “Настройка политики” в разделе Политика локального компьютера> Конфигурация компьютера> Административные шаблоны> Сеть> DNS-клиент.
- **Отключение NBT-NS** – NBT-NS можно отключить через настройки сетевого подключения. Перейдите к сетевым подключениям > Internet Protocol версии 4 > Свойства > Общие > Дополнительно > WINS, затем выберите “Отключить NetBIOS через TCP / IP”.
- **Фильтрация сетевого трафика**– для блокировки трафика LLMNR, NBT-NS и mDNS можно использовать средства защиты на уровне хоста.
- **SMB Signing (Подписание SMB)** – как упоминалось выше, подписание SMB можно использовать для предотвращения атак с ретрансляцией NTLM путем цифровой подписи передаваемых данных.

Поиск узлов без SMB подписи
```powershell
netexec smb <ip_addr>/24 --gen-relay-list smb_targets.txt
```

- **Мониторинг** – необходимо отслеживать (1) трафик на портах LLMNR и NBT-NS (UDP 5355 и 137), (2) журналы событий с идентификаторами 4697 и 7045 (относятся к ретрансляционным атакам)[[4]](https://www.cynet.com/attack-techniques-hands-on/llmnr-nbt-ns-poisoning-and-credential-access-using-responder/#post-32290-footnote-4) и (3) изменения в реестре DWORD _EnableMulticast_ в _HKLM\Software\Policies\Microsoft\Windows NT\DNSClient_.
