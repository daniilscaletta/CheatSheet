# 1) **Virtualization-based security (VBS)**

Данный механизм позволяет отделить OS от ядра и сделать виртуализацию самой Windows
Этот механизм работает при включенном Hyper-V (HyperVisor), от момента загрузки ОС


### LSASS.exe
Критический процесс который должен быть изолярован
Он отвечает за:
1) Аутентификацию, в т.ч. удаленную
2) Применение политик безопасности
3) Храненит паролей, токенов, хэшей пользователей

После ввода пароля система (LSA, куда входит LSASS.exe) передает данные в SAM (security account manager) 

**SAM** хранит и управляет учетными данными на локалке
Учетные данные хранит в виде хэша в HKLM/SAM

### SAM
Интересен Red Team и Windows, в целях безопасности SAM частично шифруется в реестре, к нему невозможно обратиться, а вот ко второй части в оперативке у нас доступ есть (если не включена функция изоляции ядра)

### Отключение хранения паролей в открытом виде

`HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\SecurityProviders\WDigest`

Установление ключа `UseLogonCredential`:
- Отсутствует - запрет
- 0 - запрет 
- 1 - разрешено

Для примененения работы этой функции нужно включить метод аутентификции WDigest:
Ключ `Negotiate - 1`

### Защита памяти _LSA_ от подключений к ней из незащищённых процессов

`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\LSA`
Ключ `_RunAsPPL_`
- отсутствует - защита отключена
- 0 - отключена
- 1 - включена

# Кэширование учетных данных

По умолчанию заложен механизм, если нет сетевого доступа до контроллера домена, то Windows кэширует 10 учетных записей:
`HKEY_LOCAL_MACHINE\Security\Cache (или на диске C:\System32\config\SECURITY`

Пароли хранятся в виде хэш + соль
