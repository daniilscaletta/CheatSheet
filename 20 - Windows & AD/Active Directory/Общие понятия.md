Технология **Active Directory** подразумевает **иерархическое построение имён на основе доменов**.

Каждый контроллер домена имеет полную и исчерпывающую информацию обо всех объектах в своём домене. Если же в домене несколько контроллеров, то они ещё и участвуют в механизме репликации, поддерживая несколько актуальных копий базы данных с объектами домена

### Домен

Домен — это структура сети Active Directory. Домены содержат такие объекты, как пользователи и компьютеры, которые организованы в контейнерные объекты: группы и организационные подразделения (OU). Каждый домен имеет свою собственную отдельную базу данных и наборы политик, которые могут применяться ко всем объектам внутри домена. Некоторые политики устанавливаются по умолчанию (и могут быть изменены), например, политика паролей домена. В отличие от них, другие создаются и применяются в зависимости от потребностей организации, например, блокировка доступа к cmd.exe для всех пользователей, не являющихся администраторами, или подключение общих дисков при входе в систему.

### Контроллеры домена

Контроллеры домена, по сути, являются «мозгом» сети Active Directory. Они обрабатывают запросы на аутентификацию, проверяют пользователей в сети и контролируют доступ к различным ресурсам в домене. Все запросы на доступ проверяются контроллером домена, а запросы на привилегированный доступ основаны на заранее определенных ролях, назначенных пользователям. Он также обеспечивает соблюдение политик безопасности и хранит информацию обо всех остальных объектах в домене.
#### **Глобальный каталог AD**

**Глобальный каталог AD** — это распределённое хранилище данных, которое хранит частичное представление обо всех _AD_-объектах в лесу. Это хранилище располагается на контроллерах домена, которые имеют дополнительную роль _Global Catalog Server_ (Сервер глобального каталога). От обычного контроллера домена _GC_-сервер отличается в первую очередь тем, что помимо полной копии всех объектов в своем домене, хранит также частичную информацию обо всех объектах в других доменах леса.

Однако, если в лесу всего один домен (как у нас), то глобальный каталог содержит полную копию объектов в домене и всё. Каждый домен в _AD_ должен иметь хотя бы один _GC_-сервер.

### Полное доменное имя (FQDN)

Полное доменное имя (FQDN) — это полное имя конкретного компьютера или хоста. Оно записывается с именем хоста и именем домена в формате [имя хоста].[имя домена].[домен верхнего уровня]. Это используется для указания местоположения объекта в иерархическом дереве DNS. FQDN можно использовать для поиска хостов в Active Directory, не зная IP-адреса, подобно тому, как при переходе на веб-сайт, например, google.com, вместо ввода соответствующего IP-адреса. Примером может служить хост `DC01`в домене `INLANEFREIGHT.LOCAL`В данном случае полное доменное имя будет следующим: `DC01.INLANEFREIGHT.LOCAL`.

### SYSVOL

Папка [SYSVOL](https://social.technet.microsoft.com/wiki/contents/articles/8548.active-directory-sysvol-and-netlogon.aspx) , или общая папка, хранит копии общедоступных файлов в домене, таких как системные политики, параметры групповых политик, сценарии входа/выхода из системы, а также часто содержит другие типы сценариев, которые выполняются для выполнения различных задач в среде Active Directory. Содержимое папки SYSVOL реплицируется на все контроллеры домена в среде с помощью службы репликации файлов (FRS).


### NTDS.DIT

Файл NTDS.DIT ​​можно считать сердцем Active Directory. Он хранится на контроллере домена по адресу `C:\Windows\NTDS\`Это база данных, которая хранит данные Active Directory, такие как информация об объектах пользователей и групп, членстве в группах и, что наиболее важно для злоумышленников и специалистов по тестированию на проникновение, хэши паролей всех пользователей в домене. После полной компрометации домена злоумышленник может получить доступ к этому файлу, извлечь хэши и либо использовать их для проведения атаки типа PtH, либо взломать их в автономном режиме с помощью такого инструмента, как `Hashcat`, для доступа к дополнительным ресурсам в домене. Если включен параметр « [Хранить пароли с обратимым шифрованием»](https://docs.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/store-passwords-using-reversible-encryption) , то NTDS.DIT ​​также будет хранить пароли в открытом виде для всех пользователей, созданных или изменивших свои пароли после установки этой политики. Хотя это случается редко, некоторые организации могут включить этот параметр, если они используют приложения или протоколы, которым необходимо использовать существующий пароль пользователя (а не Kerberos) для аутентификации.

## **WINRM**

_WinRM_ — это реализация _Microsoft_ протокола _WS-Management Protocol_ — стандарта _SOAP_, дружелюбного к брандмауэрам, который позволяет общаться аппаратному обеспечению и операционным системам различных типов

_WinRM_ позволяет осуществлять удалённое взаимодействие пользователя с системой (например, запуск файла, изменение реестра, изменение службы. Для запуска используется команда _winrm_ и другие программы, такие как _PowerShell_.

Рекомендую рассмотреть возможность отключения службы _WinRM_. Если она необходима, то изолируйте инфраструктуру с _WinRM_ с отдельными учётными записями и разрешениями.

### LDAP

Active Directory поддерживает [протокол LDAP (Lightweight Directory Access Protocol)](https://en.wikipedia.org/wiki/Lightweight_Directory_Access_Protocol) для поиска в каталогах. LDAP — это протокол с открытым исходным кодом и кроссплатформенный протокол, используемый для аутентификации в различных службах каталогов (таких как AD). Последняя спецификация LDAP — [версия 3](https://tools.ietf.org/html/rfc4511) , опубликованная как RFC 4511. Твердое понимание того, как работает LDAP в среде AD, имеет решающее значение как для злоумышленников, так и для защитников. LDAP использует порт 389, а LDAP через SSL (LDAPS) взаимодействует через порт 636.

Active Directory хранит информацию об учетных записях пользователей и информацию о безопасности, такую ​​как пароли, и обеспечивает обмен этой информацией с другими устройствами в сети. LDAP — это язык, который приложения используют для связи с другими серверами, предоставляющими службы каталогов. Другими словами, LDAP — это способ, с помощью которого системы в сетевой среде могут «общаться» с Active Directory.

Сеанс LDAP начинается с подключения к серверу LDAP, также известному как агент системы каталогов. Контроллер домена в Active Directory активно прослушивает запросы LDAP, такие как запросы аутентификации безопасности.

## **GPO**

Групповая политика — важный элемент любой среды _Microsoft Active Directory_ (_AD_). Её основная цель — дать ИТ-администраторам возможность централизованно управлять пользователями и компьютерами в домене. Групповая политика, в свою очередь, состоит из набора политик, называемых объектами групповой политики (_GPO_)

При создании домена _AD_ автоматически создаются два объекта групповой политики:

- Политика домена по умолчанию устанавливает базовые параметры для всех пользователей и компьютеров в домене в трёх плоскостях: политика паролей, политика блокировки учётных записей и политика _Kerberos_.
- Политика контроллеров домена по умолчанию устанавливает базовые параметры безопасности и аудита для всех контроллеров домена в рамках домена.

Настройки различных объектов групповой политики могут перекрываться или конфликтовать. По умолчанию объекты групповой политики обрабатываются в следующем порядке (причём созданные позднее имеют приоритет над созданными ранее):

- локальный (индивидуальный компьютер);
- сайт;
- домен;
- организационная единица.

В эту последовательность можно и нужно вмешиваться, выполнив любое из следующих действий:

1. **Изменение последовательности GPO.** Объект групповой политики, созданный позднее, обрабатывается последним и имеет наивысший приоритет, перезаписывая настройки в созданных ранее объектах. Это работает в случае возникновения конфликтов.
2. **Блокирование наследования.** По умолчанию дочерние объекты наследуют все объекты групповой политики от родительского, но вы можете заблокировать это наследование.
3. **Принудительное игнорирование связи GPO.** По умолчанию параметры родительских политик перезаписываются любыми конфликтующими политиками дочерних объектов. Вы можете переопределить это поведение.
4. **Отключение связей GPO.** По умолчанию обработка включена для всех связей _GPO_. Вы можете предотвратить применение объекта групповой политики для конкретного контейнера, отключив связь с объектом групповой политики этого контейнера.

Иногда сложно понять, какие политики фактически применяются к конкретному пользователю или компьютеру, определить так называемый **результирующий набор политик** (_Resultant Set of Policy_, _RSoP_). _Microsoft_ предлагает утилиту командной строки [GPResult](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult), который умеет генерировать отчёт _RSoP_.

Для управления групповыми политиками _Microsoft_ предоставляет **консоль управления групповыми политиками** (_GPMC_)


Взломщик или злонамеренный администратор могут легко изменить объекты групповой политики, чтобы, например:

- Разрешить неограниченное количество попыток угадать пароль учётной записи.
- Включить возможность подключения съемных носителей для упрощения кражи данных.
- Развернуть вредоносное ПО на всех машинах в домене.
- Заменить сайты, сохранённые в закладках браузеров пользователей, вредоносными _URL_-адресами.
- Запустить вредоносный сценарий при запуске или завершении работы компьютера.

Но самое ужасное во всей этой истории с безопасностью _GPO_ — изменения настроек **не отслеживаются** в собственных журналах безопасности, нет предупреждений, следовательно, невозможно отслеживать такие нарушения, даже если использовать _SIEM_-систему.
