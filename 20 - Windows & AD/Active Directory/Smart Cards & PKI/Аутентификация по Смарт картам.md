> Аутентификация по смарт картам использует аутентификацию через PKINIT по сертификатам

Для включения данного типа аутентификации используется функция `Smart card is required for interactive logon`

Данная функция приводит к:
1) Удалению всех AES и NTLM секретов
2) Перестает работать аутентификацию по паролю, только по сертификатам
3) <span style="background:#ff4d4f">ОДНАКО, [[Pass-the-Hash]] продолждает рабоать </span>

НО, это НЕ панацея, дополнительно нужно:
1) Включить авторотацию пароля при логоне, чтобы тот хэш, который где-то остался, также поменялся, и будет меняться при каждом логоне пользователя
2) Следить, чтобы не отключалась функция работы по смарт картам, иначе пароль стухнет из-за того, что по сертификату он войти уже не сможет, а пароль сратирован на непонятный хэш (По умолчанию на это есть 7 дней)

## Отрицательные стороны 

1) PIN код от смарткарты <span style="background:#ff4d4f">хранится в открытом виде в lsass.exe</span>, при этом даже не защищается Cred guard
2) По RDP также PIN код передается в открытом виде 
3) По RDP Пробрасываются все сертификаты сразу (и привилигированные и непривилигированные)
4) <span style="background:#fff88f">Чтобы не было предвычисления PKINIT необходимо включить на DC `PKINIT Freshness Extension` </span>
