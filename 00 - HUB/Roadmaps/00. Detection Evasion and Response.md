#cyberkillchain #network 

> Цель - снизить активность до минимума, чтобы ни команда обнаружения (SOC) ни антивирусные средства (EDR, EPP, XDR, IDS


### Снижение подозрительности нагрузки

1) Сигнатуры в **бинарных** файлах обнаруживаются гораздо более эффективнее чем скриптах, поэтому нагрузку лучше делать в формате скрипта (.py, .c#)
2) Нагрузки из популярных мэйкеров нагрузки очень популярны и часто обнаруживаются

### Основные принципы предотвращения обнаружения

1) Максимально снизить активность в сети
	- Исключить массовое сканирование сети
	- Использовать пассивныей сбор информации через ARP
	- Исключить массовое сканирование портов
	- Перед сканированием сервиса подумать не является ли он HoneyPotом
	- Сканировать только прикладные сервисы
	- Исключить совершение атак MiTM
2) Использовать только шифрованные каналы связи, а также передачу только шифрованных команд (С2)
3) Заранее развернуть тестовые стенды с предположительными EDR и EPP и тестировать на них обнаруживаемость своих нагрузок, упаковщиков, исполнение в памяти

##### Пример приемов снижения активности

1. Опросить DNS на предмет корневых доменных имен.

```sh
```dig domain.local
```

2. Опросить домен на предмет записей о сервисах в домене.  
  
```sh
dig -t SRV _gc._tcp.domain.local   
dig -t SRV _ldap._tcp.domain.local
dig -t SRV _kerberos._tcp.domain.local   
dig -t SRV _kpasswd._tcp.domain.local
```

3. Исследовать трафик сети на предмет широковещательного трафика: ARP, mDNS, LLMNR, NBTNS и пр.

4. Попытаться обратиться к общедоступным ресурсам, типа почты, сервера LDAP, сервера, WPAD прокси.

```sh
dig -t MX domain.local
dig -t wpad.domain.local
```

#### Подготовка нагрузок

Нагрузки детектируются 2мя типами защиты:
- Статический анализ
- Динамический анализ

##### Статический анализ
Он применяется путем анализа строк кода или байтов
Если нагрузка взята с распространенного общедоступного ресурса, то скорее всего она уже известна и будет заблокирована

**Способы обхода статического анализа:**
1) Шифрование бинарного файла (При запуске, его также необходимо расшифровать)
2) Обфускация
3) Разработка самописного инструментария
TOOL: _[DefenderCheck](https://github.com/matterpreter/DefenderCheck)_ для проверки эксплойтов на реагирование Windows Defender

##### Динамический анализ
Анализ выполнения файла в песочнице, обойти сложнее, нужно быть креативнее

**Способы обхода динамического анализа:**
1) Использовать сон перед выполнением, так как у большинства систем проверок ограниченное время на проверку. 
2) Проверять ресурсы машины, в песочнице используются небольшие ресурсы, поэтому можно покреативить с темпой процессора, вращением кулера и движением мыши, если основные параметры совпадают, то не выполняться, так как мы в sandbox
3) Проверять домен машины перед выполнением, чтобы наша нагрузка выполнялась только на предназначенной машине, а не на всех (в том числе и не в sandbox)


##### Бесфайловое выполнение скриптов
Интересный способ, где вредоносная программа хранит свои артефакты исключительно в памяти

Этот способ обходит большинство проверок EPP, так как они преимущественно настроены на ЖД

Бесфайловое выполнение блокируется следующими средствами:
1) UAC
2) PowerShell (сценарии, интерактивное использование и динамическая оценка кода)
3) Windows Script Host (wscript.exe и cscript.exe)
4) JavaScript и VBScript
5) Макросы Office VBA

Чтобы обойти такие решения нужно использовать:
1) Обфускацию
2) Патчинг в памяти
3) Отдельные трюки приостановки работы AMSI


## Инструменты генерации нагрузок с применением механизмов обфускации, шифрования и тд

1) [Veil](https://github.com/Veil-Framework/Veil) — это инструмент, предназначенный для создания нагрузок metasploit, которые обходят обычные антивирусные решения.

2) [Freeze](https://github.com/optiv/Freeze) — это инструмент создания полезной нагрузки, используемый для обхода средств контроля безопасности EDR с целью скрытного выполнения шеллкода. Freeze использует множество методов не только для удаления EDR userland hooks, но и для выполнения шеллкода таким образом, чтобы обойти другие средства контроля конечных точек.

3) [SGN](https://github.com/EgeBalci/sgn) — это полиморфный двоичный кодер, предназначенный для наступательных целей безопасности, таких, как генерация статически недетектируемых двоичных полезных нагрузок. Он использует аддитивный цикл обратной связи для кодирования заданных двоичных инструкций, подобно LFSR.


# Подмена IP

Эта опция необходимо, чтобы предотвратить блокировку узла, с которого мы атакуем жертву

Лучшим инструментом является TOR
Используется как:
1) TOR Browser
2) TOR сервис + Proxychains

Атаки на TOR клиентов:
1) Установка входных и выходных узлов сети, принадлежащим одному владельцу
2) Внедрение пакетов трафика на входе и поиск задублированных пакетов на выходе 

### **Ротация IP-адресов** 

Для постоянной смены IP адресов зачастую недостаточно пользоваться такими сервисами, как Tor или I2P, т.к. некоторые сервисы могут блокировать вас по факту принадлежности вашего IP к сетям анонимного доступа. 

Также такие сети не позволяют выполнять множественные запросы, постоянно изменяя IP с высокой скоростью.
