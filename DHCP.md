# Установление контакта между сервером и клиентом

1) Компьютер отправляет широковещательный запрос `DHCPDISCOVER` с целью узнать, присутствует ли в сети _DHCP_-сервер, который может выдать адрес нашему устройству. Адресом отправителя в этом сообщении является 0.0.0.0.

2) После получения широковещательного запроса _DHCP_-сервер отправляет `DHCPOFFER` — пакет, содержащий _IP_-адрес, который будет присвоен компьютеру. В данном случае для навигации пакета будет использован _MAC_-адрес компьютера, так как _IP_-адреса он пока что не имеет.

3) Компьютер, получив `DHCPOFFER`, высылает сообщение `DHCPREQUEST` — соглашается на выданный ему адрес. Данное сообщение рассылается всем устройствам сети, сообщая, что данный _IP_-адрес занят.

4) _DHCP_-сервер, получив `DHCPREQUEST`, резервирует выданный _IP_-адрес за _MAC_-адресом нашего компьютера и убирает этот _IP_ из пула свободных, а также отправляет `DHCPACK` нашему устройству.

5) Ещё одним важным типом сообщения является `DHCPINFORM` — так DHCP-клиент запрашивает конкретные параметры конфигурации у *DHCP*-сервера.

# WPAD (Web Proxy Automatic Discovery)

> Механизм _WPAD_ предоставляет браузеру доступ в интернет через прокси-сервер. 

Браузер находит _DHCP_-сервер, на котором размещен конфигурационный файл _wpad.dat_, и использует оттуда данные для подключения. Если же файл не был найден, то подключение в Интернет осуществляется через шлюз по умолчанию.
