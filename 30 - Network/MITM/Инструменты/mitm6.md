#MITM #Network #IPv6 #ActiveDirectory #Relay 

> **MITM6** - Эксплуатирует приоритет IPv6 в сетях Windows для захвата роли DNS-сервера и проведения атак типа [[NTLM Relay]].

## Механика атаки

1. **DHCPv6 Advertisement:**
    
    - Windows по умолчанию рассылает запросы **DHCPv6 Solicit** для поиска настроек IPv6.
    - `mitm6` отправляет ответный пакет **DHCPv6 Advertise/Reply**, назначая себя основным IPv6-шлюзом и **DNS-сервером**.
    - **Почему это работает:** Windows отдает приоритет IPv6 над IPv4. Если получен DNS через IPv6, он становится первичным, обходя настройки легитимного IPv4 DNS.

2. **DNS Poisoning:**
    
    - Став основным DNS-резолвером, `mitm6` перехватывает запросы к внутренним именам домена.
    - На запросы типа **WPAD** (Web Proxy Auto-Discovery) или обращения по коротким именам (Shortnames) инструмент выдает IPv6-адрес атакующего.

3. **Forced Authentication (Принуждение):**
    
    - Система жертвы пытается загрузить файл конфигурации прокси или подключиться к ресурсу.
    - Происходит запрос аутентификации NTLM. Жертва передает Net-NTLMv2 хеш серверу атакующего (обычно это `ntlmrelayx`).

### Точечная атака

Чтобы не шуметь в сети и бить только по администраторам:

- **Фильтр по Hostname:** `-hw <target_hostname>` (отвечать только конкретной машине).
- **Фильтр по MAC:** `-mw <mac_address>` (самый надежный способ фиксации цели).
- **Исключение доменов:** `-i <domain>` (игнорировать запросы к определенным ресурсам).

## Контрмеры

1. **Отключение IPv6:** Если протокол не используется в бизнес-процессах.
2. **LDAP Signing & Channel Binding:** Защита от релея учетных данных в службы каталогов.
3. **WPAD:** Отключение службы через GPO или создание пустой записи в DNS.
4. **DHCPv6 Guard:** Настройка портов коммутатора (Trust/Untrust) для блокировки поддельных DHCP-ответов.
