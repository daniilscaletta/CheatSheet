#tool #mitm

**Ettercap** — это инструмент для **Man-in-the-Middle (MITM)** атак в локальных сетях.  
Позволяет перехватывать, анализировать и модифицировать сетевой трафик между узлами, а также проводить активные атаки на сетевые протоколы.

Работает на **L2–L7**, основной вектор — **ARP spoofing / poisoning**.

## Для чего используется

### Основные задачи
- Перехват сетевого трафика в LAN
- Анализ протоколов (HTTP, FTP, SMB, LDAP и др.)
- Проведение MITM-атак
- Инъекция данных в незашифрованный трафик
- Демонстрация рисков отсутствия защиты (ARP, TLS, signing)

## Как работает (кратко)
1. Отравляет ARP-кэш жертвы и/или шлюза
2. Заставляет трафик идти через атакующую машину
3. Выступает как прозрачный прокси
4. Анализирует, логирует или модифицирует трафик

Ключевая идея:  
**жертвы думают, что общаются напрямую, но общаются через тебя**

## Основные возможности

- ARP poisoning (MITM)
- Sniffing трафика
- Plugin-система
- SSL stripping (устаревшее, но показательное)
- DNS spoofing
- Credential harvesting (незашифрованные протоколы)
- Passive и active режимы

## Как использовать (базово)

### 1. Выбор интерфейса

Указывается сетевой интерфейс:
- `eth0`
- `wlan0`
### 2. Определение целей
- конкретный хост
- диапазон IP
- шлюз

### 3. Запуск MITM-атаки
Обычно через ARP poisoning.

## Пример использования (базовый MITM)

### Сценарий

- Атакующий: `192.168.1.50`
- Жертва: `192.168.1.100`
- Шлюз: `192.168.1.1`

### Команда

```bash
ettercap -T -q -i eth0 -M arp:remote /192.168.1.100/ /192.168.1.1/
```
- `-T` — текстовый режим
- `-q` — тихий режим
- `-i eth0` — сетевой интерфейс
- `-M arp:remote` — MITM через ARP spoofing
- `/target1/ /target2/` — жертва и шлюз

Результат:
> весь трафик между жертвой и шлюзом проходит через атакующего

## Пример с плагином (DNS spoofing)

```baah
ettercap -T -q -i eth0 -P dns_spoof -M arp:remote /192.168.1.100/ /192.168.1.1/
```

Используется для:
- подмены DNS-ответов
- редиректа на фишинговые страницы
- демонстрации риска отсутствия DNSSEC / HTTPS

### Защита
- Dynamic ARP Inspection (DAI)
- HTTPS + HSTS
- Network segmentation
- IDS/IPS
- ARP monitoring

## Важные замечания
- Легко детектируется
- Устаревает по сравнению с:
    - bettercap
    - mitmproxy
