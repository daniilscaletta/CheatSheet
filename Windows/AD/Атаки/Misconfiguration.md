#ActiveDirectory #windows 

> Очень огромное количество настроек которые могут привести к полной компрометации домена или хотя бы причинить ущерб

## 1) PrivExchange

**PrivExchange** — это классическая и очень опасная цепочка атак, которая позволяет рядовому пользователю домена за считанные минуты стать **Doman Admin**.

Суть в том, что сервер Exchange по умолчанию имеет слишком высокие привилегии в Active Directory (группа `Exchange Windows Permissions`), что позволяет ему изменять ACL объектов домена.

### Эксплуатация
https://swisskyrepo.github.io/InternalAllTheThings/active-directory/CVE/PrivExchange/


## 2) MS14-068

Билет Kerberos содержит информацию о пользователе, включая имя учетной записи, идентификатор и членство в группе в сертификате атрибутов привилегий (PAC). Сертификат PAC подписывается KDC с использованием секретных ключей для проверки того, что сертификат PAC не был изменен после создания.

Уязвимость позволяла KDC принимать поддельный PAC как легитимный. Это можно использовать для создания фальшивого PAC, представляя пользователя как члена группы администраторов домена или другой привилегированной группы

### Эксплуатация

https://swisskyrepo.github.io/InternalAllTheThings/active-directory/CVE/MS14-068/

## 3) Перечисление DNS-записей

Если в результате перечисления с помощью таких инструментов нам возвращается соглашение об именовании хостов. `BloodHound`похож на `SRV01934.INLANEFREIGHT.LOCAL`Если все серверы и рабочие станции имеют неинформативные имена, нам сложно понять, что именно нужно атаковать. Если же у нас есть доступ к записям DNS в Active Directory, мы потенциально можем обнаружить интересные записи DNS, указывающие на тот же сервер, например: `JENKINS.INLANEFREIGHT.LOCAL`которые мы можем использовать для более эффективного планирования наших атак.

### Эксплуатация

```bash
adidnsdump -u 'domain'\\'user' ldap://'ip' -r

Password:
```

## 4) Пароль в Description

```powershell
Get-DomainUser * | Select-Object samaccountname,description |Where-Object {$_.Description -ne $null}
```

## 5) Поле PASSWD_NOTREQD

Если оно установлено, на пользователя не распространяется текущая политика длины паролей, что означает, что у него может быть более короткий пароль или вообще не быть пароля (если в домене разрешены пустые пароли). Пароль может быть установлен как пустой

```powershell
Import-Module .\PowerView.ps1

Get-DomainUser -UACFilter PASSWD_NOTREQD | Select-Object samaccountname,useraccountcontrol
```

## 7) Злоупотребление объектами групповой политики (GPO)

Групповая политика предоставляет администраторам множество расширенных настроек, которые можно применять как к пользовательским, так и к компьютерным объектам в среде Active Directory. При правильном использовании групповая политика является отличным инструментом для повышения безопасности среды Active Directory путем настройки параметров пользователей, операционных систем и приложений. Однако следует отметить, что групповая политика также может быть использована злоумышленниками не по назначению.

Неправильная настройка групповых политик может быть использована для осуществления следующих атак:

- Добавление дополнительных прав пользователю (таких как SeDebugPrivilege, SeTakeOwnershipPrivilege или SeImpersonatePrivilege)
- Добавление локального администратора на один или несколько хостов.
- Создание запланированной задачи для выполнения любого количества действий.
